# 后续研究与自测

这些是基于今天学习提出的工程与研究方向，不是 Voyager 已完成的功能，也不是当前已授权执行的项目。

## 结合 Rosso 背景的切入点

后端/API、分布式系统经验可以直接用于技能的行为契约、幂等性、依赖、版本与观测；已有生产 Applied AI 经验和个人 Agent/RAG/记忆探索保持区分，不把个人实验写成工作成果。

### 1. 从“成功程序”到“可靠技能”

建议技能记录包含：描述、代码、前置条件、预期后置条件、依赖版本、执行证据、适用环境、已知失败、验证日期。定义可重试与不可重试的失败，避免中途失败后盲目重复副作用。

实验：同一技能在不同背包、资源位置、部分完成状态下执行；测成功率、重试次数、错误分类和总成本。

### 2. 从语义相关到实际可用的检索

比较仅描述向量检索，与加入前置条件过滤、依赖检查后的检索。再用理想技能选择作上界对照，区分检索失败和代码生成失败。

指标：候选相关性、实际可执行率、任务成功率、上下文 token 和总调用费用。不要只优化相似度。

### 3. 验证器作为经验入库入口

先在低风险模拟环境中，对比 LLM critic、状态差分、事件日志和混合验证。重点测误判成功导致的错误技能入库及后续传播。

指标：假阳性、假阴性、入库技能后续复用成功率。让检查覆盖任务结果，而不只是程序是否正常退出。

### 4. 从个人工具箱到共享库

多个 Agent 的成果共享需要版本、去重、兼容性、质量门槛、回滚和失效机制。先定义谁能写入、以什么证据晋升为稳定技能，以及如何撤回失效版本。

这与课件“文明”类比相关，但先用可测的小规模实验验证，不预设共享一定带来增益。

## 下次读论文可以追问

1. 成功判定检查的是结果状态，还是本轮行为？哪些任务仅看背包无法确认？
2. 从任务成功到技能入库之间，有没有额外泛化验证？
3. 保存的函数依赖哪些旧函数，部署和更新时怎样保持依赖一致？
4. 技能越多后，检索和代码上下文成本是否抵消复用收益？
5. 相同 token、实际时间或费用预算下，优势是否仍存在？
6. 不同环境、更多随机种子下，哪些结论仍稳定？
7. 换成 RPG 时，哪些接口和结果检查可以复用，哪些必须重做？

## 快速自测与答案要点

- 三个器官？自动课程、技能库、迭代提示机制。
- 三个 GPT-4 角色？curriculum、actor、critic；后两者都在迭代机制内。
- critique 干什么？说明未完成原因并提出改进建议，可能出错。
- 技能库 key/value？描述向量／程序代码。
- 为什么说模型没变但系统学了？持久技能与上下文改变了后续行动能力。
- 一次成功能否证明技能可靠？不能，需要变化条件下的复用验证。
- option 的三部分？何时可启动、怎样行动、何时终止。
- 160 轮是否是 160 个任务或 160 次总 API 调用？不能这样等同。
- 三个消融陷阱为什么都不对？性能下降不等于系统完全不能工作。
- 能否拿 VPT 与 Voyager 的成功率直接比？感知、动作、目标和预算不一致。
- 多 Agent 共享库为何比单 Agent 入库更难？质量、版本、依赖和失败传播的治理问题。
