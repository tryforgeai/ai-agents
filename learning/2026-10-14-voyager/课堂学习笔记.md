# Voyager：今天真正理解了什么

## 1. 核心问题：模型没变，为什么系统变强？

Rosso 对“学到后面并没有更聪明，只是装备更充分”提出质疑。这个质疑应保留：学习方法、识别模式和积累经验本来可以算实际能力增长，不能用人类学习的类比断言大脑没有变化。

准确表述：Voyager 不更新底层 LLM 权重，但外部技能库、任务历史和每次调用的上下文会变化，所以系统行为和任务表现可以改善。技能库变大并不自动证明能力变强，仍需要在可比条件下测成功率与成本。

还要区分游戏进度与可迁移能力：第 160 轮已有装备，不能只凭它比第 1 轮强就归因于学习。清空背包、换世界、保留技能库的实验更能检验经验迁移。

## 2. 三个器官与三个模型角色

| 系统模块 | 职责 | 模型角色 |
|---|---|---|
| 自动课程 | 按状态和历史提出下一任务 | GPT-4 curriculum |
| 技能库 | 保存并检索可执行程序 | 存储与检索；GPT-3.5 写描述 |
| 迭代提示机制 | 生成、执行、修正、检查 | GPT-4 actor 与 critic |

三个模块不是三个 GPT-4 实例的一一对应。自验证属于迭代提示机制；“另一个 GPT-4”指另一个角色或调用上下文，不是重新训练模型。

闭环：选任务 → 检索技能 → 生成代码 → 环境执行 → 反馈和检查 → 成功入库；不成功则修改，最多四轮后记录失败并换任务。失败任务可以以后再尝试。

## 3. Agent 怎样自己写 skill？

模型已有编程能力。外围程序提供任务、当前状态、基础 API、检索到的旧技能和可复用代码要求。GPT-4 输出 JavaScript；运行环境执行；错误与状态进入下一轮提示；成功后保存程序。

“今天需要解决的任务，成为明天可以调用的函数”是本次最有用的理解。

基础操作由人和运行库提供；Agent 在其上生成更高层程序。技能金字塔课件明确是示意，不是某次运行真实调用图。高层函数可以调用旧函数，但适用条件变化时仍需调整。

## 4. 自动课程：选什么任务

依据背包、装备、附近资源、生物群系、时间、健康、饥饿、完成和失败任务，选择新的目标。提示要求兼顾新颖性和可行性：不要一直重复，也不要超出现有资源和技能太多。

课件例子：有木镐和石料就做石镐；河边有鱼竿就钓鱼；缺食物且附近有猪就获取食物；有粗铁、煤、熔炉就冶炼；有剑盾且附近有僵尸就尝试战斗。这些是不同状态的示例，不是固定线性课程。

“in-context novelty search”强调以提示和上下文驱动探索，并非训练新的选题模型。

### 热身安排（课件 p.36，论文 Table A.1）

| 完成任务数 | 课程模块新增信息 |
|---|---|
| 0 | 核心背包、装备、附近方块、位置 |
| 5 | 附近生物 |
| 7 | 完整背包 |
| 10 | 最近见过的方块、生物群系 |
| 15 | 血量、饱食度、时间、额外上下文 |

这是课程模块的输入安排，不等于整个 Agent 无法获取那些状态。按完成数而非调用数解锁。早期聚焦基础任务是合理解释，但不能据此宣称已证明这种安排最优。

GPT-3.5 的自问自答整理已有游戏知识，为选题增加上下文；课件称 Wiki 可选。模型并非从零发现全部游戏规则。

## 5. 技能库：存什么、如何找

- Value：程序代码。
- Key：GPT-3.5 所写自然语言功能描述的 embedding；不是直接对代码做 embedding。
- Query：任务的解题建议加环境反馈的 embedding。
- 返回 top-5 相关技能，供生成代码参考和调用；不要求五个全部执行。

制作铁镐可以检索到冶炼、木棍、工作台等前置技能，而不必只有名称含“铁镐”的函数。可把它理解为检索描述、返回程序的 RAG 用法。

提示词显式要求函数通用、检查所需物品、命名有意义。可组合性不能仅靠“写成代码”保证。

## 6. 三种反馈与 critique

| 反馈 | 来源 | 作用 |
|---|---|---|
| 环境反馈 | 交互程序输出 | 如“还缺 7 块铁锭” |
| 执行错误 | 运行时和解释器 | 函数不存在、语法或操作错误 |
| 自验证 | GPT-4 critic 读取任务和状态 | 判断成功，并提出改进意见 |

Rosso 问 critique 做什么：它解释为什么未完成、下一轮可以怎样改。success 是判定，critique 是诊断建议。程序没有报错，不代表任务完成。

Fig.6 的关键局限：从煤炭、羊毛、羊肉、腐肉推断采集或击杀结果，只是间接证据。已有物品、掉落差异和其他来源都可能造成误判。两块羊毛并不是严格的击杀计数器。

工程延伸：比较执行前后状态、记录事件，能够确定性验证的条件优先用规则；这些是改进建议，不是原系统的完整实现。

## 7. 为什么代码，以及 option 类比

代码可跨多个时间步执行、可检查、可组合，还能运行以获得反馈。它封装细节，减少上层重复规划。

option 的三个概念：启动集合 I、执行策略 π、终止规则 β。课件用描述、程序、critic 对应它们，是启发性映射：描述相似不保证启动条件成立；终止不等于成功；critic 的任务成功判断不等于完整的终止函数。

搜索空间示意 b^H → b_Ω^(H/k̄)：技能平均封装 k̄ 步，可以缩短高层决策链。不是 Voyager 的实测复杂度定理，也没有消除底层动作。

## 8. 实验怎样读

主探索预算每次 160 提示迭代，每方法三次。一次迭代不是一个任务，不等于相同 token、费用或时间。作者为 Minecraft 适配的 ReAct、Reflexion、AutoGPT 代表特定实现，不能推广到所有同名系统。

课件按附录计数：Voyager 为 63、58、67 种物品，AutoGPT 为 11、22、25；均值约 62.7 和 19.3，比值 188/58≈3.24。一位小数为 3.2，摘要 3.3 的差异应注明，原因未核实。物品种类不等于技能数。

无技能库曲线仍约 37 种，表明其余机制也贡献显著。完整系统后期继续增长，是技能库增量价值的证据，但不证明无限增长。

| 方法 | 木工具 | 石工具 | 铁工具 | 钻石工具 |
|---|---:|---:|---:|---|
| AutoGPT | 92±72 | 94±72 | 135±103 | 0/3 |
| 无技能库 Voyager | 7±2 | 9±4 | 29±11 | 0/3 |
| 完整 Voyager | 6±2 | 11±2 | 21±7 | 102，1/3 |

前三列三次都成功，数字是提示迭代统计。15.3× 是木工具 92/6；不能当墙钟加速。石工具无库样本均值较小，不能用 n=3 宣称复用开销造成退化；木工具完整系统略优，不能写成“木、石都不如无库”。

消融问答：无库仍能探索；GPT-3.5 写代码仍能运行；无 critic 不意味着任何任务都不能完成。组件贡献不等于逻辑上的必要条件。

## 9. 技术背景与比较边界

VPT 与 Voyager 感知、动作接口不同：前者图像与键鼠，后者文本状态与代码 API。2.5% 与 1/3 的成功口径和预算不同，不可算提升倍数。

GITM 是 Ghost in the Minecraft，与 Voyager 同日提交，关注结合文本知识和记忆的分层任务分解与行动规划。

课堂六条路线：规模、微调、提示、检索、工具、保留操作经验。它们可以组合。“Voyager 之前只能靠重训保留改进程序”是过强表述，保存外部程序本来就不要求重训。

成本页：VPT 数字是训练与数据投入；Voyager 的“每次几十美元”是讲者按历史价格粗估，论文未报告该账单。不能拿完整训练投入与单次调用费用精确比较倍数。复用基础模型降低新增实验投入，不意味着预训练成本消失。

## 10. RPG 与经验传承

Rosso 问能否玩 RPG：架构可以迁移，仍需适配状态与行动接口。只有屏幕与键鼠时还需感知和实时控制；动作游戏通常需要更快的底层控制器。不能说原 Voyager 可直接玩任意 RPG。

课程最后用骑兵冲锋比喻有限的推理资源，用黄铜工艺比喻经验传承。个人技能库、跨世界迁移、借给 AutoGPT，与多个 Agent 共同维护技能库是不同层次。

共享库还需要验证、版本、依赖、冲突处理、失效和撤回机制。“文明”是启发性的类比，不是本论文的实验结论。

## 11. 追加：消融汇总（22:29 截图，课件 p.59）

该页指标仍是 160 次提示迭代后的不同物品数。以下按课件转录；带约号的虚线柱是课件近似值，不作为原始精确统计。

| 设置 | 课件结果 |
|---|---|
| 完整 Voyager | 63 |
| 随机课程 | 比完整系统下降 93% |
| 人工课程 | 约 17；约 45 轮后趋平，采用十任务清单 |
| 无技能库 | 约 36；约 120 轮后趋平 |
| 无自验证 | 下降 73% |
| 无环境反馈 | 约 25 |
| 不提供执行错误反馈 | 约 26 |
| GPT-3.5 负责代码生成 | 完整系统物品数约为其 5.7 倍 |

此前对曲线的口头读数约 37，与本页约 36 都是读图近似，不应伪装为精确矛盾。5.7 倍按 63 作示意换算约为 11；不是下降 5.7%。

解释：合适的选题、代码生成能力和成功检查均影响探索；无技能库仍能取得不少前期进展，库有助于后续积累。移除执行错误反馈不意味着运行中不再发生错误，只是不把这类信息反馈给生成者。

这些是完整系统附近的一次一项替换／移除实验。下降比例不能相加，也不是各组件独立贡献份额。随机课程是替换策略，不是完全没有课程；人工课程是一份特定清单，不代表所有人工设计。跨指标的重要性排序可能不同。
