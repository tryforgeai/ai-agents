Enterprise RAG

Permission-Aware Retrieval

Enforce permissions with deterministic infrastructure at the moment of retrieval, not by asking the model to behave afterwards.

8 points · what, then why · use ← → to navigate

1 / 8

Authorization is a hard constraint, not a score

Compute the allowed set D_u first, then search only inside it.

D_u = { d ∈ D : Authorized(u, d) = 1 }
d*  = argmax sim(q, d)   over d ∈ D_u
Why: as a score term, a relevant-enough confidential doc can outweigh its missing permission. Similarity measures "how alike", never "may you see this". The better the retriever, the more precisely it leaks.
2 / 8

Prevent, don't suppress

Filter at retrieval → secret never in prompt
Prevention · a control
Secret in prompt + "please don't reveal"
Suppression · a request
Why: once text is in the prompt, "don't reveal it" is one prompt injection away from the output. Infrastructure filtering is deterministic; the model never gets the chance.
3 / 8

Pre-filter, never post-filter

Pre-filter: 10 allowed results
Post-filter: top-10 → silently top-2
Why: searching top-10 then deleting 8 leaves 2. Recall drops and nobody notices.
4 / 8

A normalized security descriptor on every chunk

{ "tenant": "acme", "classification": "confidential",
  "allow_groups": ["finance","executives"], "deny_users": [],
  "regions": ["US"], "acl_version": 17 }
Why: retrieval happens per chunk. Chunking keeps content but drops permissions, and an index can't filter in five source-system dialects at once.
5 / 8

Missing = deny · deny beats allow · versioned

Why:
  • Missing metadata is where systems fail open; uncertainty must default to deny.
  • An explicit deny (e.g. conflict of interest) must not be overridden by a group grant.
  • After an incident, replay the decision as it was, not from today's state.
6 / 8

Sync entitlements by event, not TTL

10:01
doc indexed
10:05
permission revoked
10:06
query → leak
Why: content rarely changes; permissions change constantly (joiners, movers, leavers). The sync gap is the leak window. Azure AI Search has the same gap.
7 / 8

Under the hood: bitmaps, then search inside

allowed = B[tenant] ∩ (B[user] ∪ B[groups…]) ∖ B[deny] ∩ B[class] ∩ B[region]
small set → brute force
large set → bitmap-aware HNSW
1–10% → graph breaks: partition / ACORN
Why: a permission change only updates bitmaps, with no re-embedding, so sync is fast. Low selectivity disconnects the graph, so benchmark recall there.
8 / 8

Cover all six leakage surfaces

Retrieval
Context
Answer
Citations / metadata
Cache
Logs / traces
Why: filenames, cache hits and traces are side channels around content filtering. Even "I found X.pdf but you can't open it" discloses X.pdf exists.
Takeaway

Filter before you search.
Never ask the model to keep a secret.
