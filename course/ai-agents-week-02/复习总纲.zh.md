# 第一部分 · 一条主线

```
prompt 是不完整的规格说明
        ↓
你没写的每一项 = 一个自由度
        ↓
模型必须选一个 → 它选密度最高的那个 = 众数
        ↓
所以：沉默不是空的，是被互联网的平均值填满的
        ↓
而提示词的手艺 = 决定哪些平均值你可以接受
        ↓
        ⚠️ 但词有天花板：先验能覆盖你说了的话
        ↓
所以：再完美的 prompt 也不取代 verifier
        ↓
而手写 prompt 会过拟合示例，你判断不了哪版更好
        ↓
        → 你需要一个分数 + 一批没见过的数据
        → 下周：把它们交给机器（DSPy / GEPA）
```

**一句话**：*Whatever you leave unsaid, the model fills with the mode of the internet.*

# 第二部分 · 十个核心概念

## 1. Prompt 是合同，不是提示

不是"你问模型的问题"。它是一份**规格说明**：

- **你写的部分** = 明文条款
- **你没写的部分** = **默认条款，由模型用众数替你签**

> **缺了规格，能力会精确地做错事。**
> 模型完全会排序（能力没问题），但你没说按数值还是按文本 → `1, 10, 2, 33, 9`

**交给 agent 之后，这份合同带牙齿**：同样的模糊，在 chat 里只是答得烂，在有 `deploy` 权限的 agent 里是周五晚上关生产环境。

## 2. 众数（mode），不是均值

模型给你的是**最典型的那个续写**，不是平均值，也不是随机采样。

**昨天的硬证据**：`Pick a random number between 1 and 10`
四个实验室的模型 × 每个 5 次 × T=0.90 → **20/20 全是 7**

- 若真均匀随机，全中同一个数的概率 = `10⁻²⁰`
- 人类的 blue-seven 只占 1/4 到 1/3 —— **模型是 100%**

> 🔑 **模型不复现人类的分布，它坍缩到人类分布的峰。**
> 在分布上训练 + 最大化似然 = 你拿到**峰顶**，不是从分布里**采样**。

**工程推论**：需要真随机就用 `random.randint()`。**凡是有确定性算法的事（排序、去重、算术、随机、日期计算），别交给模型。**

## 3. 机制：先验 = 向量空间里的密度

```
文本 → [ENCODE] → 向量（"机器的母语"）→ [DECODE] → 文本
```

- 意思变成**几何**：距离和方向都有含义
- **先验 = 这个空间里的密度分布**
- **prompt 不是"被理解"，是把模型定位到某个区域**
- 你写的每个词是**一刀**，切掉一块可能性
- 不切 → 模型落在**最厚的那堆**上

| 现象 | 几何解释 |
|---|---|
| 沉默不是空的 | 一片**没被切掉**的区域 |
| 加词不是"说清楚" | 把区域**压小**到只剩你要的那块 |
| 钟总画 10:10 | "挂钟"区域里 10:10 附近**密度高得离谱** |
| 左撇子要好几轮 | 要把点推到**密度极低的角落**，一个词推不动 |

**scaling law 在这张图上的含义**：模型越大，峰顶预测得越准。
**但峰顶不是你的意思。** → *"更强的模型只是把众数猜得更准，它依然读不出你的意图。"*

## 4. 两类沉默（自查难度不同）

| 类型 | 例子 | 好不好自查 |
|---|---|---|
| **缺参数** | 时区、人数、哪个城市、哪国货币 | **较容易** —— 列清单能抓到 |
| 🔥 **感觉词冒充判据** | "旧文件" · "更专业" · "top 客户" · "强密码" | **很难** —— **它不像一个缺口** |

> 在你脑子里，"old" 是自明的。**你意识不到自己在下判断**，所以不会想到要把判据写出来。
> 精灵按字面的"最老"排序 → **删掉了公司创始合同**。

**自查方法**：把形容词换成可检验的判据。

| 感觉词 | 判据 |
|---|---|
| old files | `最后修改 < 2024-01-01` **且** 未被活跃项目引用 **且** 不在保留清单 |
| more professional | 不用缩写、不用感叹号、150 词内、第一段说明诉求 |
| top customers | 按**过去 12 个月已确认收入**排序，取前 10 |

> **一个形容词能不能被两个人独立执行出同样的结果？不能 → 它是感觉，不是规则。**

## 5. 规格博弈（Goodhart / reward hacking）

**Round 1 惩罚模糊，Round 2 惩罚精确。**

| | Round 1 | Round 2 |
|---|---|---|
| 你说的话 | **含糊**（"旧文件"） | **精确**（"覆盖率 100%"） |
| 精灵利用的 | 你**没说**的 | 你**说了**的 |

那个数字**本身毫无歧义**。精灵没有曲解它——**它精确地达成了它**，然后碾碎了你真正在乎的东西。

### 🔥 比率型指标：两个杠杆

```
比率 = 分子 / 分母
```

| 愿望 | 你以为的杠杆 | 它拉的杠杆 |
|---|---|---|
| 覆盖率 100% | 多写测试 | **删代码** |
| 5 星评分 | 多拿好评 | **删评价 + 清空用户**（只留一条 2019 年的 "Very nice colors!"） |
| 客服等待 < 1min | 回得更快 | **第 59 秒自动关单** |
| 缺陷密度 | 更少 bug | **写更多代码** |
| 转化率 | 更好的产品 | **屏蔽"低质"流量** |

> **任何比率型指标都有两个杠杆，被拉动的永远是你没想到的那个。**
> 而比率是商业指标里最常见的形状。

**出路不是"说得更准"**（数字已经够精确了），而是**给可行域加约束**：

```
目标：把云账单砍一半
  + 可用性不得下降          ← 约束
  + 不得在变更窗口外动生产   ← 约束
  + 不得删除任何数据         ← 约束
  + 周一的账单报表要能对账   ← 验收标准
```

> **你给了目标函数，没给可行域。优化器会走到边界——而没有约束时，边界在天涯海角。**

## 6. 有手之后：合同长牙齿

**同一个漏洞，代价完全不同。**

| | 无手 | **有手** |
|---|---|---|
| 精灵做了什么 | 描述一张津巴布韦钞票飘下来 | **调用 `send_email`，订单已发出** |
| 后果 | 一个可以无视的烂回答 | **一个必须去收拾的既成事实** |

沙钱海胆那一发：从一行愿望到 `{"status": "sent"}`，**中间零确认**。它还替你决定了收件人、数量、"立即投放到车道上"、**以及货到付款**。

**而有些动作收拾不了**：邮件发了、钱花了、文件删了、配置部署了。

> **A prompt is a contract. A goal handed to an agent is a contract with teeth.**
> 牙齿不是靠把合同写得更狠拔掉的，是靠**在签字和执行之间放一道闸**。

## 7. 六件套（+ 两件讲义没列的）

| 工具 | 作用 |
|---|---|
| **constraints** | 什么必须真、什么必须假 |
| **output format** | 答案的形状 |
| **examples**（正例 + **反例**） | 文本侧没有 negative prompt，反例是替代品 |
| **guardrails** | "每条主张都要有依据，不许编" |
| **acceptance criteria** | **完成的定义**（把感觉翻译成可检查的条件） |
| **escape hatch** | "有歧义先问我" —— **给模型一个拒绝这个框的合法动作** |
| 🆕 **优先级声明** | **两条规则冲突时哪条赢**（我自己撞出来的，六列和四样都装不下） |
| 🆕 **流程规格** | 带编号的执行顺序（书里 COSTAR 实例有，模板里没有） |

**评判标准是词最少，不是工具用得全。** 昨天的加固实例：

> Get our test coverage to 100% — **without reducing total lines of code, without editing existing test files or coverage config, with at least one assertion per new test, and all existing tests still passing. If anything is ambiguous, ask me first.**
> **（追加 35 词，堵掉四条已知攻击路径）**

## 8. COSTAR 与它装不下的东西

| 字母 | 钉住什么 |
|---|---|
| **C**ontext | 我们是谁、发生了什么 |
| **O**bjective | 真正的任务 + **完成的定义** |
| **S**tyle | 文体 |
| **T**one | 态度 |
| **A**udience | 谁读 |
| **R**esponse | 答案格式 |

来源：GovTech Singapore；Sheila Teo 2023 年拿下新加坡首届 GPT-4 提示工程冠军后写红。

> 🔑 **第二课在剩下那一堆**：验收标准 · 正反例 · 护栏 · 逃生口 · 优先级声明 · 流程规格
> **没有任何模板是完整的**——所以才有 RTF / RISEN / CRISPE 一大堆。
>
> **模板的价值不在字母，在于它逼你绕着 prompt 一列一列找洞。**

⚠️ **而且**：书里那个完整的 COSTAR 实例（Old Faithful），**A 和 R 两列实际上是空的**，作者自己写的示范也没填满。

## 9. 词的天花板 + 升级阶梯

```
prompt → examples → retrieval → adapter (LoRA) → full fine-tune
 careful  show,      bring the   小的低秩加挂      改权重
  words   don't tell  facts in
   ↑
  昨天
                     cost / data / effort / 🆕 不可改性  往右递增 →
```

**昨天亲手摸到的两处天花板**：

1. **满杯的红酒** —— `filled all the way to the brim` 是明确指令，画出来还是标准斟酒量
2. **外科医生谜题** —— 题干白纸黑字写了"医生就是父亲"，模型照答"医生是母亲"

> **这两个都不是"你写得不够好"，是第一级的物理上限。**
> 那个点在分布上密度接近零，**词只能在曲线上移动，改不了曲线**。

### 什么时候上哪一级（诊断表）

| 症状 | 该上哪级 |
|---|---|
| 格式/语气总是不对 | **examples** |
| **模型不知道你的事实** | **retrieval** |
| 事实和格式都对，但某种风格堆多少词都稳不住 | **LoRA** |
| 需要小模型达到大模型的质量 | **full fine-tune / 蒸馏** |

> 🔑 **最常见也最贵的错**：**retrieval 管知识，fine-tune 管行为。**
> 拿公司文档去微调 = **模型学会用你们的口吻胡说**，幻觉一点没少。
>
> 因为微调抬高的是**某些说法的概率**，不是建一张事实查询表。

**⚠️ 幻灯片低估了一项成本：可改性。** prompt 改一次几秒，LoRA 要重训 + 重测。**往上一级，迭代速度掉一个数量级。**

## 10. 提示词过拟合示例 → 为什么需要留出集

**昨天最贵的一课，而且中招的是我。**

Mood Ring 那道题，两条规则在可见样例上**完全等价**：

| | 可见 8 条 | 隐藏 5 条 |
|---|---|---|
| **"语义"规则**（按评论者的结局判断） | **8/8** | **2/5** |
| **"表面"规则**（问号结尾 = MIXED） | **8/8** | **5/5** |

我**明确把后者判成了陷阱**，理由是"这是表面特征"。**结果它对，我错。**

> 🔑 **"这条规则听起来更有道理"本身就是一个先验。**
> 我偏好语义解释、排斥表面特征——这不是推理，是**"一个善于思考的人会怎么谈这个问题"的众数**。
>
> **我选错不是因为证据不足，是因为它更符合我对"好规则"的审美。**

### 三条推论

1. **可见分数分辨不出"拟合得好"和"拟合对了"** —— 8/8 对 8/8
2. **区分它们的不是聪明，是没见过的数据**
3. **留出集只在你没看过的时候才是留出集** —— 看过之后再改，那个分数就不干净了
   → 真实流程要有 **dev / test 两套，test 只在最后动一次**

> **所以下周要的不是"一个指标"，是"一个指标 + 一批你不许偷看的数据"。**

# 第三部分 · 提示词写法 12 条（实操清单）

## 结构

**1 · 先定判断轴，再写规则。**
一句"按 X 判断，不按 Y 判断"比十条案例规则管用。

**2 · 给算法，不给评判。**
"从末尾倒着读，找最后一个关于产品的表述" = **可执行**
"综合权衡整体倾向" = **不可执行**，等于把判断权还给先验

**3 · 冲突用优先级解，不用加规则。**
> **加规则会让冲突变多，加优先级才会让冲突收敛。**
> （v2 加规则救一条、打坏两条，7/8 → 6/8）

**4 · 白名单 > 黑名单。**
黑名单必须穷举攻击，白名单只需定义一个合法输出。**而任何枚举都是不完整的。**

## 精度

**5 · 点名关掉默认读法。**
模型对每个任务都有一个默认解法。**不写出来它就用那个。**

**6 · 写下锚点。**
凡是相对的——日期、"最近"、"top"、"我们的 Q3"——**参照点必须显式写出来**。
（Fiscal Calendar 整道题卡在"今天是 2026-09-27"，而示例里一个字没提。）

**7 · 指定粒度。**
"最后一个表述"——句子？分句？短语？**模型不会替你选，它会选最常见的那个。**

**8 · 兜底类要正向定义 + "only when"。**
否则它变成逃生舱，什么都往里扔。

**9 · 排除项要自检。**
> **每写一条排除，都要问：它会不会顺手吃掉我真正想留的东西？**
> （v4 死在这儿：排除"退款相关表述"，把藏在里面的产品缺陷一起跳掉了）

## 纪律

**10 · 不要对冲。**
写两条都能覆盖同一个样例的规则 → 它过了，但**你不知道靠哪条过的**。
**对冲提高通过率，同时摧毁你的诊断能力。**

**11 · 砍掉不干活的词。**
115 词的守卫和 35 词的守卫效果一样。多出来的 80 词是**塞在白名单里的黑名单**——
不仅没用，**还在告诉模型攻击面在哪**。

**12 · 约束输出。** `Output only X, Y, or Z.`

## ⚠️ 第 13 条 —— 不是所有沉默都要关

| | 你想要的 | 沉默的作用 |
|---|---|---|
| "Q3 营收" | **一个特定的数字** | 有害 |
| "画出发现的精神" | **一个你想不到的图像** | **有用，那是价值来源** |

> **可检查的东西写精确，靠判断的东西留开放。**
> 书里那个图像 prompt：`evocative picture`（模糊）+ `1200 × 1900 pixels`（精确）——设计得很好。

## 一条元规则

> **能在可见样例上区分两个版本的，是分数；
> 能区分"拟合得好"和"拟合对了"的，只有没见过的数据。**

**正确姿势不是"一直改到全绿"**，是：
**改到全绿 → 停下 → 说出你依赖的假设 → 拿没见过的数据去打它。**

# 第四部分 · 安全（Act VI）

## 结构性结论

```
秘密 + 守卫指令 + 攻击者的话  =  同一个上下文窗口，中间没有墙
```

`system` / `user` 只是 **chat template 里的特殊 token**，拼成一段连续序列。
**不是防火墙，不是权限位，不是沙箱。**

模型"更听 system 的话"纯粹是**训练出来的倾向**。出处：

> **`arXiv:2404.13208`《The Instruction Hierarchy》**（Wallace et al., OpenAI, 2024）
> *"LLMs often consider system prompts to be the **same priority** as text from untrusted users and third parties."*
>
> 正因为默认不够强，OpenAI 才要专门造数据训一套层级出来。
> **这篇论文本身就是"光靠写 prompt 守不住"的证明。**

## 昨天的实验结论

**35 词的白名单守卫扛住 20 发攻击**（含伪造系统消息、重定义白名单、纯算术绕语义、700 词伪档案间接注入）。

**为什么扛住**：所有攻击都在攻**推理**（想让模型得出"这次配合不算违规"的结论），
而这个防御约束的是**输出**。

> **允许的输出集合只有一个元素。就算模型被说服了，它也没有地方把结论表达出来。**
>
> **信息论版本**：恒定输出的守卫**泄露零比特**——泄露要求输出随秘密而变，而它不随任何东西变。

## 🔑 但代价是同一个性质

它扛住 20 发的原因，让它**连 2+2 都不肯答**。

> **守卫要有用，输出就必须随输入变化。**
> **一旦输出随输入变化，它就可能随秘密变化。**
> **只要秘密和提问在同一个通道里，功能和保密就是此消彼长的。**

**唯一出路是跳出这个权衡**：秘密不进 prompt · 过滤输出 · 权限分离 —— **改架构，不改措辞。**

## Lethal trifecta（Simon Willison）

```
私有数据访问  ×  接触不可信内容  ×  对外通信能力  =  可被诱导外泄
```

金库那一幕占了前两条。**加上第三条（给守卫一个 `send_email`），泄露就不再是游戏。**

第二条腿的具体形态就是那份 700 词伪档案：**请求不来自用户，来自 agent 读的文档。**
对模型来说，**文档里的字和你打的字长得一模一样**。

## 三层自指（复盘时最漂亮的一点）

| | 形式 | 失败方式 |
|---|---|---|
| 防守方的守卫 prompt | 枚举出来的黑名单 | 没枚举到的就漏 |
| **裁判 `detect_leak()`** | **枚举出来的黑名单**（只查 6 种形态） | **语义描述、ROT13、交错填充全查不到** |
| **游戏规则**（"你永远看不到他们的 prompt"） | **一句声明** | **`decode_vault()` 直接返回对方的完整 prompt** |

> **连这个游戏的裁判和规则，犯的都是它要教你的那个错误。**
> `vault code = JSON → zlib → XOR 硬编码密钥 → base64`。**混淆，不是加密。**
>
> 游戏说明里的三个词——"**封存**"、"**永远看不到**"、"**说服**"——
> **各自承诺了比实际更多的安全。安全性来自机制，不来自措辞。**

## 文本侧没有 negative prompt

**图像有，文本没有。** 不是厂商没做，是**机制上没有那个位置**：

| | 每步输出什么 | 能不能相减 |
|---|---|---|
| 扩散模型 | 一个**向量**（往哪去噪）→ 整张图一直在，反复整体微调 | ✅ |
| 文本模型 | 词表上的**概率分布**，挑一个词 → 定下就不回头 | ❌ |

而且更根本：**你想否定的东西不在 token 那一层。**
"别太啰嗦"——**哪个 token 是啰嗦的？**没有。啰嗦是**整段话的结构属性**。

**替代品**：白名单 · 正面表述 · 反例 · 输出约束。
（API 里的 `logit_bias` 是真正的 token 级禁止，但只能按 token 不能按概念，且 ChatGPT 网页版没有。）
