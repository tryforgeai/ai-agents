## 1. 从 Week06 接过来（pp.1–9）

Week06 手工修改工具的 description/schema/error，观察行为再验证。本周把循环中的文本修改交给模型，但保留人对任务定义、数据和评价的责任。优化不是微调权重；它搜索能让已有模型更好完成任务的输入配置。

企业案例先解决的是 resolution gap：几十种风险不一定适合共用一个 prompt 和一套判分。先区分子问题和漏报代价，再谈自动优化。数据集要有唯一认可版本、负责人和变更记录，否则优化目标会随错误标签漂移。

三条主线：

- 数据：坏示例会通过反思被写成新规则。
- 指标：优化器会认真放大评分函数里的漏洞。
- Tether：领域定义、校准规则等关键文本不能随候选改写而变化。

## 3. 形式化与三类困难（pp.14–15）

程序 Φ 包含模型调用、工具和控制流；文本参数 θ=(π,δ)，π 是 instructions，δ 是 demonstrations。目标是在真实任务分布 D 上最大化期望评分：

```text
θ* = argmaxθ E[(x,y)~D] μ(Φ(x;θ), y)
```

保持冻结的是模型权重。修改文本参数与训练权重是不同的优化对象。

| 困难 | 为什么影响优化 | 工程后果 |
| --- | --- | --- |
| 离散且巨大 | token 字符串没有直接可用的连续导数，枚举不可行 | 生成少量有根据的候选 |
| 有噪声 | 样本有限，推理有随机性 | 单次更高不能直接接收为真实改善 |
| 昂贵 | 每次评估可能是一整条 agent 轨迹 | 记录 rollout 与反思成本、设置预算 |

讲义例：二元成功率 p=0.7、n=50，标准误约 sqrt(0.7×0.3/50)=0.065。这是估计不确定性的提醒，不是证明任何两个 prompt 永远不可区分；比较时还需看配对结果和实验设计。

Pseudo-gradient 是用文字指出失败原因与改动方向，例如“日期含 AM/PM，但工具要求 HH:MM”。它不具备真实梯度的线性、局部方向和链式法则保证。把术语理解成基于反馈的候选生成，避免把比喻当成数学机制。

讲义的五模块例 0.9^5≈0.59，是在每阶段条件成功率均为 0.9 等简化假设下的示意；不要拿它代替真实流水线测量。

## 4. GEPA：两个池、七步循环（pp.16–19）

讲义介绍 Genetic-Pareto：冻结权重，保留多个候选，用失败轨迹驱动反思改写。

- Feedback pool：产生小批次轨迹，供反思模型看具体失败。
- Pareto pool：对候选逐样本打分，参与保留和选择；它仍受到搜索压力，不是最终独立测试集。

按讲义的教学算法，先评估 seed，然后重复：

1. 从实例 frontier 中选择 parent，实例胜出数量影响抽样。
2. 选一个模块改写，讲义使用 round-robin。
3. 在 feedback minibatch 上运行 parent，收集文本反馈。
4. 反思模型修改该模块 instruction，生成 child；另有跨 lineage merge。
5. 在同一 minibatch 上比较，child 胜过 parent 才进入下一步。
6. 对通过者在整个 Pareto pool 上评估，加入候选池。
7. 清理被其他候选逐实例支配的候选。

预算结束，按 Pareto 集总分选最终候选，再做独立 holdout 评估。这里是讲义算法摘要，后续运行应核对实际库实现和配置，不能将七步摘要当逐行源码。

两阶段门槛：先花小成本筛掉差候选，再花大成本评估幸存者。讲义举 3 个样本、通过率 20%、大池 200 个，child 评估简化成本 3+0.2×200=43；这个式子未包含所有 parent 运行、反思模型和 merge 成本。

## 5. Frontier 的轴是实例（pp.17–18）

讲义强调论文版关注“哪个候选在什么样本上擅长”，不是默认画质量/成本两根轴。A 支配 B：每个实例分数都不差，且至少一个实例严格更好。

**自拟手算例，不是 kit 答案：**

| 候选 | 样本 1 | 样本 2 | 样本 3 | 平均 |
| --- | --- | --- | --- | --- |
| A | 1.0 | 0.8 | 0.1 | 0.633 |
| B | 0.3 | 0.4 | 1.0 | 0.567 |
| C | 0.8 | 0.7 | 0.1 | 0.533 |

A 支配 C；A 和 B 互不支配。只保留平均最高的 A 会丢掉擅长样本 3 的 B。

注意数学非支配集与“至少一个坐标拿第一”的集合并非普遍等价。可在课堂问：算法维护的是完整非支配集、实例赢家集合还是它们的子集？讲义的示例恰好两者一致，不能据此推广。

讲义称 2026-10 的库提供 instance/objective/hybrid/cartesian，不同入口默认值不同。这是待核实的版本信息；运行前记录安装版本和 frontier 配置，不根据笔记直接安装指定旧版本。

## 6. Metric 要返回可操作反馈（pp.19–21）

一个 0 分只能说明不满足评分；“证据段缺失、类别错误、输出 schema 错误”能让反思模型知道改哪里。下面是**自拟结构示例，不是库 API**：

```python
{
    "score": 0.4,
    "feedback": "类别正确，但证据为空；需要引用输入中的原文位置。",
    "checks": {"category": True, "evidence": False}
}
```

记录任务成功、约束违规、成本分别是什么，避免一个平均数把违规抵消掉。评分可被机器检查时优先保留可复核证据；需要 LLM judge 时写明 rubric、固定版本并用人标样本校准。

LLM judge 的典型偏差：位置、偏爱长回答、偏爱自身风格、评判标准漂移。讲义引用无 rubric 46.4%、有 rubric 73.8% 的特定研究结果；未独立核查，不能当所有 judge 的通用准确率。

## 7. 数据三分与最终验证（p.20）

| 集合 | 被如何使用 | 可以说明什么 |
| --- | --- | --- |
| Feedback / train | 反思直接读取例子和失败 | 用于改写，不能证明泛化 |
| Selection / Pareto | 多轮筛选赢家 | 可做开发比较，但存在选择偏差 |
| Clean holdout | 冻结赢家后最终评估 | 在约定实验范围内估计泛化 |

“只用一次 holdout”指不要拿最终测试结果反复选 prompt；可以预先约定对同一冻结赢家跑 3–5 seeds，但不能根据测试结果再调参仍称其 clean。

报告：baseline 和 winner 的配对差值、seed 均值/离散程度、分片结果、token/成本、版本和数据快照。切片尤其看关键风险类，不能只看总分。人工重编优化后的 prompt 也是新候选，需要重新验证，不能沿用旧分数。

## 8. Tether、intron 与何时不优化（pp.21–22）

Tether 是不可编辑文本区段的硬约束。讲义用 KL 作类比，但固定 span 与 KL penalty 不是同一种数学操作。对于必须遵守的业务规则，还应像 Week06 一样在执行端校验，文本不变不等于模型必然遵守。

Intron：反思把数据里的偶然共性概括成规则。例如所有高风险训练样本恰好含金额，候选便把“含金额”当高风险证据。识别方式是人工逐条审查、移除可疑句做消融、补反例。

判断是否值得优化：先确认 seed 还有可测 headroom、metric 抵抗投机、模型具备任务能力、预算合理。Headroom 测试用的样本一旦参与选变体，就是开发集，不再是最终 clean holdout。

讲义的“49% 优化后变差”限定为某研究 72 次运行、一个模型、四任务、六方法；不能外推为所有优化方法成功率只有一半。其论文、数据及统计都待核查。

风险类可分别设置 Fβ；β>1 更重 recall。但“更重 recall”不意味着允许无限误报，应明确业务代价和硬约束。

## 9. 按优化对象选方法（pp.23–25，讲义映射）

| 对象 | 讲义介绍的方法 | 要追问 |
| --- | --- | --- |
| 短 prompt | GEPA | 反馈是否足够、是否过拟合 |
| 增长的 playbook | ACE | 增量写入如何去重、处理矛盾 |
| skill 文件 | SkillOpt / gskill | 编辑范围、失败记忆、验证 gate |
| 数值阈值 | 校准；讲义称 ReAnchor 为实验性功能 | 其实需改阈值还是需改 prompt |
| 程序分解结构 | 讲义称 Flex 为实验性功能 | 代码执行边界、结构变更如何评估 |

讲义对比：SkillOpt 偏向带失败记忆的严格改进门槛；SkillNEO 允许继续编辑暂时更差的版本，探索后续收益。关键权衡是探索与利用，不是新方法必然更好。具体 API、性能数字需要另行查原始来源。

ACE 的增量上下文维护连接到 Week08 memory：一次性重写可能丢掉积累的内容；追加、更新、删减也需要一致性和回归检查。

## 10. 联系自己的项目（自拟应用方向，尚未实施）

- Verifiable Commerce Agents：把退款意图、政策合规、工具副作用和最终成功分开记分；金额/权限等约束不能靠总分补偿。先冻结任务与验证器，再比较文本改写。

- 商户实体匹配经验：可借领域知识思考不同商户/交易切片的误匹配与漏匹配成本；仅作学习类比，不引入雇主数据，也不假定要改生产系统。
