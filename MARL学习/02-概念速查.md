# 概念速查与阅读提醒

下面是为学习路线编写的简释。定义和推导可对照 [DI-engine 基本概念](https://opendilab.github.io/DI-engine/10_concepts/basic_rl_zh.html)、[《动手学强化学习》](https://hrl.boyuai.com/)。

| 概念 | 用库存补货理解 | 自测 |
|---|---|---|
| 智能体 agent | 为某类商品作补货决策的控制器 | 它控制什么？ |
| 环境 environment | 库存、订单、到货、销售等随时间演化的系统 | 一次动作会怎样影响下一步？ |
| 状态 state | 让环境转移可由当前信息描述的变量 | 是否包含在途订单与必要的需求状态？ |
| 观测 observation | 控制器当时实际能读到的信息 | 有哪些状态不可见？ |
| 动作 action | 本次订购数量 | 数量是否离散、是否有上限？ |
| 奖励 reward | 按所选定义计算的当期收益或负成本 | 是否漏了缺货或积压成本？ |
| 回报 return | 沿时间累积的奖励，常带折扣 | 提高今天收益会损害明天吗？ |
| 策略 policy | 根据观测选动作的规则或模型 | 规则怎样决定订多少？ |
| V 与 Q | V 评估当前情况；Q 评估当前情况中一个具体动作 | 二者是否都考虑后续奖励？ |
| actor 与 critic | actor 决定动作；critic 为学习提供估值 | critic 输出的是值还是动作？ |
| 参数共享 | 多个同类智能体使用同一套网络参数 | 输入中如何区分智能体？ |
| 信用分配 | 从团队表现理解各决策的贡献 | 团队成功由谁促成？ |

基础回报练习采用约定：第 t 次行动后获得 r_t，则 G_t = r_t + γr_(t+1) + γ²r_(t+2) + …。有些教材把第一项编号为 r_(t+1)，读公式时先统一下标。

## MARL 中需要分清的事

**非平稳性和随机性不同。**固定分布下每天销量不同，是随机性；销量分布随季节发生变化，是一种非平稳性。其他智能体不断更新策略，也会让一个智能体所面对的有效环境发生变化。

**CTDE 是信息使用方式。**训练时 critic 或 mixing network 可以利用更多信息；部署时各 actor 或局部 Q 网络依靠允许的本地信息行动。集中训练不意味着只有一个 critic，也不意味着部署时必须通信。

**参数共享和信息集中不是一回事。**两个智能体可以共享 actor 参数，但各自只输入本地观测；是否共享参数与 critic 能看见什么信息要分别说明。

## 对 DI-engine MARL 页的两条补充

该页适合作为分类导航，但阅读时注意：

1. **价值分解不等于直接拆分奖励。**QMIX 把局部动作价值组合成联合动作价值，以单调性支持分散选动作。它不要求先手工为每个智能体分配一份团队奖励。参见 [QMIX 原论文](https://arxiv.org/abs/1803.11485)。
2. **独立学习的效果取决于任务和实现。**不要把独立 PPO 理解成必然无效；把它作为实验基线，再测集中式 critic 是否带来收益。PPO 类方法在合作任务中的实际表现和实现因素可参考 [MAPPO 论文](https://arxiv.org/abs/2103.01955)。
