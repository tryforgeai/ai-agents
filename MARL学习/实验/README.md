# 实验安排

这里列出待执行任务。当前没有安装依赖、运行训练或产生实验结果。

每个实验复制一份 [实验记录模板](实验记录模板.md)。学习初期至少使用 3 个训练种子进行基本稳定性检查；严谨研究需要根据方差与预算进一步设计实验。

## 实验 A：看懂多智能体环境

资料：[MPE2 Simple Spread](https://mpe2.farama.org/environments/simple_spread/)、[Parallel API](https://pettingzoo.farama.org/main/api/parallel/)。

任务：选择少量智能体，从随机策略开始；打印 reset 和 step 的返回值、观测形状、动作空间，以及每个智能体是否终止。保存一段轨迹，解释奖励发生变化的原因。

固定记录：智能体数量、奖励设置、动作类型、回合长度、随机种子、包版本。

验收：环境能完成一个回合，且能说明观测、动作、奖励怎样按智能体对应。分别理解任务真正终止和时间上限截断，并核对训练实现怎样处理二者的 bootstrap。

## 实验 B：IPPO 与 MAPPO 对照

资料：[MAPPO 原论文](https://arxiv.org/abs/2103.01955)、[官方实现](https://github.com/marlbenchmark/on-policy)。

任务：在实验 A 的配置上，依次评估随机策略、IPPO、MAPPO。先使 IPPO 正常训练，再引入集中式 critic。若参考作者旧环境实现，应先核对和适配环境接口、数据形状及奖励语义。

控制变量：环境、训练交互预算、奖励定义、评估回合数量；是否共享参数应一致或明确作为额外变量报告。

|---|---|---|---|---|---|

| IPPO | 待定 | 待定 | 待运行 | 待运行 | |
| MAPPO | 待定 | 待定 | 待运行 | 待运行 | |

验收：画一张训练曲线、给一张独立评估结果表，并解释差异。训练回报不能直接充当最终测试结果，所有方法使用一致的评估规则。

## 实验 C：MABIM 库存补货

资料：[微软介绍](https://www.microsoft.com/en-us/research/articles/mabim/)、[代码与运行说明](https://github.com/victoryxl/replenishmentenv)。

任务顺序：

1. 选单仓任务，核对动作如何转换为订货数量，奖励中计入哪些成本。
2. 运行 Base-stock 基线，检查库存与补货可视化。
3. 使用仓库提供的 IPPO 入口进行训练与独立评估。
4. 保持其他设置不变，仅减小仓库容量，再次比较。
5. 记录收益、缺货和平均库存或占用。如果环境未直接输出某项指标，明确公式后从轨迹计算。

避免数据泄漏：训练与测试需求序列分开；仅以训练或验证数据确定基线参数及超参数。README 中含 hindsight 命名的策略，要检查是否使用未来信息；若使用，它只能作为信息更充分的参照，不能与现实可执行策略混成公平对照。

验收报告回答：IPPO 在什么容量下优于或劣于规则策略？差异是否跨种子稳定？收益改善是否伴随更高缺货？哪些判断仍需更多实验？

环境说明：MABIM 的 README 表示 MARL 训练只在 Linux 测试。启动时再选择合适运行环境并锁定依赖；当前未验证 Mac 训练兼容性。
